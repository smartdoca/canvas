# 大画板性能测试与优化（2026-09-13）

结论：数据量会显著影响性能。0.4.0 在1万元素下出现约0.6秒的选中延迟、约1秒的模型编辑到画面更新，以及约67秒的导出阻塞。0.4.1 已消除本轮测到的主要平方级开销和全量图层DOM，但没有实现无限规模、Worker渲染或增量远端校验。

## 测量方法

- 同一台 macOS、Node24.15、Chrome152，浏览器视口1400×900；使用隔离的100/1000/5000/10000个稳定ID元素，80%矩形、20%中文短文本，无真实用户数据/网络。
- Node每种规模执行5次getValue、单元素patch、对端applyUpdate及100个锚点解析，取中位数；初始化、恢复/checkpoint单次计时。两个模型最终投影必须一致。
- 浏览器每种规模使用新页面。挂载、选中、编辑包含两帧等待；导出计时包含真实Blob生成（PNG包括栅格化），验证无local update。DOM统计不是整个浏览器内存统计。
- 下表是一次可复现对比记录，不是所有设备SLA，也不是统计显著性研究；冷启动、JIT/GC和机器负载可使小数波动。原始数据见 [performance-0.4.1-results.json](performance-0.4.1-results.json)。

## 实际修改

1. getValue同级列表由每次复制整个数组改为原地追加到局部新建数组，消除根层平方级复制；对外依然返回隔离副本。
2. model.patch通过Y.Map ID直达目标，校验完整目标属性后在一个事务中改差量；保留rough/resource规范化、非法字段原子拒绝、Y.Text、本人撤销。不改变分组/排序的正式scene适配规则。
3. resolveAnchor只读取请求ID的存在/删除状态，不再为每个评论重建并校验整张场景。
4. 图层列表虚拟化，DOM数量由元素总量改为与视口高度相关；固定48px行高，深层名称省略，不删除模型节点。
5. CPU采样确认离屏Leafer Group的getBounds/localTransform/getPath/textDrawData每次都全树layout。导出在完成布局后，通过绑定Leafer2.1的内部重入保护复用只读结果；finally释放并销毁副本，绝不锁定活动编辑器。升级Leafer必须重新做几何和输出文件回归。

## 复杂素材仍有成本

- 真实生成PNG并解析、强制解码/绘制及读取像素：1024²约5.4ms、2048²约12.3ms、4096²约39.1ms。不是仅计Image.onload或文件头。样本是高压缩率纯色图片，不能代表照片/噪声/超大文件的全部性能。
- 100个斜线手绘矩形SVG约50ms/465KB；500个约657ms/2.32MB。大量手绘的路径生成、逐对象几何规范化和图案数量仍昂贵；未将1万普通元素的结果套用到1万手绘。
- 单文件10MiB、普通SVG2MiB、图片最多3200万像素；导出边长8192、3200万像素、倍率0.1～4上限不变。仅RGBA输出缓冲在3200万像素时就约128MB，实际浏览器还有额外内存，不是“只占128MB”。
- **没有测量进程峰值内存或低内存移动设备**。DOM数量大幅减少不能替代内存压测，也不能保证达到硬上限仍流畅。

## 保持的边界和剩余限制

schemaVersion=1、epoch、checkpoint身份、旧锚点、outbox/ACK合同不变；不需迁移或清空用户队列。远端仍在隔离副本严格验证后应用，未为了快而绕过未知根/字段/未闭合依赖校验。

1万元素下原生编辑约166ms、模型编辑到画面约209ms，仍会有可感知延迟；远端每次全状态验证约105ms，高频流量下仍可能阻塞。新增元素、分组/排序、完整视图投影、搜索和文本分支等路径仍可能扫描全量，不是所有操作都已增量化。超过10000元素（含模型tombstone）依旧拒绝，不自动截断。

实践上，普通短文本/基础图形约1000元素的本次测量接近几十毫秒；5000以上适合评估拆分画板，密集手绘/大图片应更早按实际内容测量。这是基于本机数据的建议，不是统一设备性能承诺。后续若Doca实际场景仍不足，应再做增量视图投影、批处理/Worker方案及峰值内存验证；不能通过删除协同安全检查来提速。

## 回归与复现

源码：28/28模型测试、27/27真实Chrome测试通过（完整浏览器约85秒，含60秒静置零更新）。新增虚拟列表滚到底部后选中/隐藏/删除/undo、万元素SVG节点数和零写入、单元素patch与正式scene适配等价和原子失败断言。万元素SVG设置宽松5秒回归门槛，用于捕捉原来的67秒故障，不是跨设备SLA。

原有中文emoji、旋转组、箭头、手绘、图片的实际PNG/SVG输出，与0.4.0验收文件SHA-256完全一致；仍为真实SVG，没有为了性能改成截图。

yarn build:lib

# 图片能力建设计划

> 下文保留单机图片编辑计划。0.2.0 Doca 模式的编辑结果须经宿主 uploadImage 上传，文档仅保存返回的稳定 path；展示与下载分别授权，不直接回写 Data URL。当前接口与取消边界见 [README](../README.md#资源)。

## 设计边界

图片在主画布中始终是普通 Leafer 元素。尺寸、透明度、位置、旋转和层级属于画布能力；裁剪、像素调整和抠图属于独立图片编辑器。编辑器只在确认时输出新的 Data URL，用户可以覆盖原元素，也可以在原元素右侧生成新元素。

能力基线参考 Cropper.js、Filerobot Image Editor、miniPaint 和 IMG.LY background-removal-js。裁剪层已正式采用 Cropper.js 2.x，负责裁剪框、图片平移缩放、比例约束、旋转、翻转和高质量 Canvas 输出；滤镜和结果编码由隔离的原生 Canvas 完成。

## 技术阶段

1. 保持弹窗编辑器和 Leafer 场景完全隔离。
2. 将像素运算拆到 Web Worker / OffscreenCanvas，避免大图阻塞主线程。
3. AI 模型采用动态加载，不进入首屏包；首次使用明确显示下载体积和进度。
4. 大图和编辑结果由 IndexedDB Blob 管理，画布文档只保存素材 ID，避免 localStorage 容量溢出。
5. 每个阶段补充跨 Chrome、Safari 和内置浏览器的视觉回归。

## 智能能力依赖决策

- 人脸检测优先采用 MediaPipe Tasks Vision，并放入 Web Worker；只保存检测框和关键点，不保存人脸数据。头像构图由本地规则根据人脸框生成 1:1、3:4 与可调头肩范围。
- 背景移除必须在独立 Provider 中动态加载。候选 IMG.LY background-removal-js 的 AGPL 许可证会影响项目分发方式，确认兼容前不直接写入运行时依赖。
- 蒙版修正使用双画笔（保留/移除）和边缘羽化；发丝优化、局部修复及内容填充分开建设，避免把远程 AI 伪装成纯浏览器本地能力。
- 批量处理复用同一参数快照，以任务队列串行/低并发执行；多尺寸导出使用命名模板并打包 ZIP，避免同时持有大量 Data URL。
